  <action>
Two files need changes:

**packages/cli/src/output.ts** — Export a `printBadArgs` function:

1. Add a new exported function `printBadArgs(message: string, opts: OutputOpts = {}): never` immediately after `printFailure`.
2. In human mode: write `pc.red('Error: ') + message + '\n'` and `pc.dim('code: BAD_ARGS') + '\n'` to `process.stderr.write`.
3. In machine mode: write `JSON.stringify({ error: { code: 'BAD_ARGS', message } }) + '\n'` to `process.stderr.write`.
4. Call `process.exit(EXIT.BAD_ARGS)` at the end. Return type is `never`.

This keeps the output contract centralized — all error formatting stays in output.ts.

**packages/cli/src/index.ts** — Wire Commander's error path:

1. Import `CommanderError` from `commander` (named export alongside `Command` and `Option`).
2. Import `printBadArgs` from `./output.js` alongside the existing `EXIT` import.
3. Call `program.exitOverride()` immediately after `program.showSuggestionAfterError(true)` and before `.addOption(...)`. This makes Commander throw `CommanderError` instead of calling `process.exit()` directly.
4. In the existing `program.parseAsync().catch((err: unknown) => { ... })` handler, add a guard BEFORE the existing fallback:
   ```
   if (err instanceof CommanderError) {
     // Commander error codes: 'commander.unknownOption', 'commander.missingArgument',
     // 'commander.missingMandatoryOptionValue', 'commander.invalidArgument', etc.
     // Version/help use 'commander.version' and 'commander.helpDisplayed' with exitCode 0.
     if (err.exitCode === 0) process.exit(0);
     const opts: OutputOpts = { json: program.opts().json, human: program.opts().human };
     printBadArgs(err.message, opts);
   }
   ```
5. Keep the existing UNKNOWN_ERROR fallback for non-Commander errors after the new guard.

IMPORTANT: Commander's `exitOverride()` also intercepts `--help` and `--version` which throw `CommanderError` with `exitCode: 0`. The guard `if (err.exitCode === 0) process.exit(0)` handles these cleanly. Do NOT apply BAD_ARGS to exitCode 0 errors.

Do NOT use `configureOutput` — `exitOverride` is the cleaner approach because it lets us catch errors in a single place (the `.catch()` handler) rather than intercepting write streams.
