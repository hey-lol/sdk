3. **update** (PROF-03): No positional args. MUST add four optional options to the command chain BEFORE `.action()`:

```typescript
.option('--name <string>', 'display name')
.option('--bio <string>', 'profile bio')
.option('--avatar <url>', 'avatar image URL')
.option('--banner <url>', 'banner image URL')
```

In the action handler, build a partial `UpdateProfileParams` object from whichever flags were provided. Map `opts.name` to `params.displayName` (the SDK field name differs from the CLI flag name). Send whatever fields were provided — empty object is valid (server returns unchanged profile). No guard for "at least one flag" is needed.

```typescript
.action(async function (this: Command) {
  const opts = this.optsWithGlobals<GlobalContext & {
    name?: string;
    bio?: string;
    avatar?: string;
    banner?: string;
  }>();
  try {
    const client = createClient(opts);
    const params: UpdateProfileParams = {};
    if (opts.name !== undefined) params.displayName = opts.name;
    if (opts.bio !== undefined) params.bio = opts.bio;
    if (opts.avatar !== undefined) params.avatarUrl = opts.avatar;
    if (opts.banner !== undefined) params.bannerUrl = opts.banner;
    const profile = await client.profile.update(params);
    printSuccess(profile, opts);
  } catch (err) {
    printFailure(err, opts);
  }
});
```

**Flag name mapping rationale:** The success criteria specifies `--name` and `--bio` (short, CLI-ergonomic). The SDK uses `displayName`, `bio`, `avatarUrl`, `bannerUrl`. Map `--name` to `displayName`, `--avatar` to `avatarUrl`, `--banner` to `bannerUrl`. `--bio` maps directly to `bio`.

**Anti-patterns to avoid:**
- Same as Task 1: no arrow functions, no raw string where `UserId` expected, no `console.log`.
- Forgetting `import type { UpdateProfileParams }` — TypeScript won't find the type.
- Using `asPostId` instead of `asUserId` for the profile get command.
