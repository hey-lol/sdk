Install publint and attw as root devDependencies:
```bash
pnpm add -Dw publint @arethetypeswrong/cli
```

**Validate publint passes on all packages:**
```bash
for pkg in packages/*/; do
  echo "=== publint: $pkg ==="
  pnpm --filter "./$pkg" exec publint
done
```
If publint reports errors, fix the package.json exports maps before proceeding.

**Validate attw passes on SDK package:**
```bash
cd packages/sdk && pnpm exec attw --pack .
```
If attw reports errors (e.g., `false-cjs`, `false-esm`), fix the exports map or tsup config. If attw reports `cjs-resolves-to-esm` warnings for adapter packages that are ESM-first, consider creating a `.attw.json` in those packages with `{"ignoreRules": ["cjs-resolves-to-esm"]}` — but only if they genuinely don't support CJS require.

**Configure size-limit:**

Create `.size-limit.json` at workspace root:
```json
[
  {
    "path": "packages/sdk/dist/index.mjs",
    "limit": "100 kB",
    "import": "*"
  },
  {
    "path": "packages/sdk/dist/services.mjs",
    "limit": "100 kB",
    "import": "*"
  }
]
```

Verify size-limit is already installed (should be from plan 01 root devDependencies along with @size-limit/preset-big-lib). If not installed, add them:
```bash
pnpm add -Dw size-limit @size-limit/preset-big-lib
```

Add a `"size-limit"` key to root package.json or use `.size-limit.json` file (file approach preferred for cleanliness).

Add a size-check turbo task script to SDK's package.json if needed, or rely on the root `"size-check": "size-limit"` script.

Run `pnpm size-check` to verify it reports sizes and passes the 100 KB gate.

**1. Initialize changesets:**
```bash

```
This creates `.changeset/config.json` and `.changeset/README.md`. After init, verify the config has:
- `"access": "public"` (set this if not already — required for scoped @heylol packages)
- `"baseBranch": "main"`
- `"fixed": []` and `"linked": []` (empty = independent versioning, which is the default)
- `"updateInternalDependencies": "patch"`

Update `.changeset/config.json` if needed to set `"access": "public"`.

Verify changesets works: `pnpm changeset status` should run without errors.

**2. Create GitHub Actions CI workflow** (`.github/workflows/ci.yml`):
Follow Pattern 9 from RESEARCH.md. Key details:
- Trigger on push to main and pull_request (opened, synchronize)
- Use `pnpm/action-setup@v4` with version 9
- Use `actions/setup-node@v4` with node-version 20 and pnpm cache
- Run `pnpm install --frozen-lockfile`
- Run `pnpm turbo lint build typecheck test size-check` (single turbo command, parallelized by task graph). The `test` task runs `vitest run --coverage` in each package, which enforces 90% coverage thresholds configured in root vitest.config.ts — if any package drops below 90% lines/functions/branches/statements, the CI step fails.
- Separate step for publint and attw validation on each package in packages/
- TURBO_TOKEN and TURBO_TEAM as optional env vars (from secrets/vars)

Note: Coverage enforcement requires no additional CI configuration — vitest's `coverage.thresholds` in the root vitest.config.ts causes `vitest run --coverage` to exit non-zero when thresholds are not met, which naturally fails the `turbo test` task and the CI step.

**3. Create GitHub Actions release workflow** (`.github/workflows/release.yml`):
Follow Pattern 10 from RESEARCH.md:
- Trigger on push to main only
- Same pnpm/node setup
- Use `changesets/action@v1` with publish command `pnpm changeset publish`
- GITHUB_TOKEN and NPM_TOKEN env vars

**4. Set up husky pre-commit hook:**
```bash
pnpm exec husky init
```
This creates `.husky/pre-commit`. Replace its content with just `lint-staged` (which is configured in root package.json lint-staged field from plan 01).

Verify the hook works:


The lint-staged config from plan 01 root package.json runs `biome check --write` on staged JS/TS/JSON files.
