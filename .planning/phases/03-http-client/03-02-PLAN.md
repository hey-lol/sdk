**1. Create src/client/HeyLolClient.ts** — The main client class. Follow the research skeleton closely but adapt to actual Phase 2 APIs.

Key design decisions:
- Constructor takes `ClientOptions`, calls `loadKeypair(opts.privateKey)` to get the `Keypair`, stores resolved options.
- `request<T>(method, path, body?)` is the core method. It contains the 402 loop inline (NOT delegated to a separate function) with a `paymentHeader` variable (initially null) as the loop guard.
- The 402 loop calls `parsePaymentRequirements(response)` (async, consumes body), then `buildDummyTransaction(keypair.publicKey, keypair.secretKey)` to build+sign the tx in one call, then `buildPaymentHeader(requirements[0], signedTx, version)`.
- `AbortSignal.timeout(this.timeout)` is created INSIDE the attempt closure so each retry gets a fresh signal.
- `request()` calls `withRetry(attempt, { retries: this.retries, sleep: ... })`. The `attempt` function throws `RateLimitError` on 429 (with parsed `retryAfterMs`) and `APIError` on non-ok responses — `withRetry` handles the retry decision.
- For 429: parse `Retry-After` header using `parseRetryAfterMs()` and pass to `RateLimitError` constructor.
- For non-ok non-402 non-429: throw `APIError` with `statusCode`.
- Catch fetch failures (TypeError, DOMException) and wrap in `NetworkError` with appropriate code ('TIMEOUT' for AbortError/TimeoutError, 'FETCH_FAILED' for others).

Typed method wrappers — thin pass-throughs:
```typescript
async get<T>(path: string): Promise<T> {
  return this.request<T>('GET', path);
}

async post<T>(path: string, body?: unknown): Promise<T> {
  return this.request<T>('POST', path, body);
}

async patch<T>(path: string, body?: unknown): Promise<T> {
  return this.request<T>('PATCH', path, body);
}

async delete<T>(path: string): Promise<T> {
  return this.request<T>('DELETE', path);
}
```

Important implementation notes:
- `buildDummyTransaction(publicKey, secretKey)` takes public key AND secret key (it signs internally). Do NOT try to call `ed25519.sign` separately.
- `getPaymentVersion(response)` returns `1 | 2 | null`. If null on a 402, default to version 1.
- Do NOT read response body before checking status 402 — `parsePaymentRequirements` consumes the body.
- Set `Content-Type: application/json` and `Accept: application/json` headers on all requests.
- When `paymentHeader` is set, add it to request headers: `headers[paymentHeader.headerName] = paymentHeader.headerValue`.
- Store the `Keypair` object on the instance, never the raw base58 private key string.
